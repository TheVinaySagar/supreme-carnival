## 1. Data & Cache Structure

### 1.1 Price Data Cache

**Location**: `tradingagents/dataflows/data_cache/`

**Format**: CSV files named `<TICKER>-YFin-data-<START>-<END>.csv`

**Example File**: `HDFCBANK.NS-YFin-data-2024-09-01-2024-12-31.csv`
- Source: Yahoo Finance (via yfinance library)
- Contains: 83 daily trading days (Sep 1 – Dec 31, 2024)
- Columns: Date, Open, High, Low, Close, Volume, Adj Close
- Loaded automatically by `TradingEnvironment._load_price_data()` in `rl_environment.py`

**Weekly Sampling Logic** (from `rl_environment.py`):
```python
all_dates = list(self.price_data.keys())  # 83 trading days
self.trading_dates = all_dates[::5]       # Every 5th day → 17 trading periods
```

**Result**: 17 weekly trading periods from the 83-day dataset

### 1.2 LLM Reports Cache

**Location**: `tradingagents/dataflows/data_cache/llm_reports/`

**Format**: JSON file named `<TICKER>_<START>_<END>.json`

**Example File**: `HDFCBANK.NS_2024-09-01_2024-12-31.json`
- **Structure**: Dict with 17 entries (one per weekly trading date)
- **Keys**: Trading dates in format `TICKER_YYYY-MM-DD`
  - Example: `HDFCBANK.NS_2024-09-02`, `HDFCBANK.NS_2024-09-09`, ..., `HDFCBANK.NS_2024-12-27`
- **Fields per entry** (6 reports):
  ```json
  {
    "HDFCBANK.NS_2024-09-02": {
      "market_report": "Technical analysis summary...",
      "sentiment_report": "Social/retail sentiment...",
      "news_report": "Company/macro news...",
      "fundamentals_report": "Financial metrics...",
      "bull_report": "Bullish thesis with arguments...",
      "bear_report": "Bearish thesis with risks..."
    }
  }
  ```

**Report Sources**:
- **Analyst Reports** (4): Generated by `TradingAgentsGraph` which runs 4 LLM-based analysts:
  - **Market Analyst**: Technical indicators, price patterns, volatility
  - **Sentiment Analyst**: Social media, Reddit, retail sentiment
  - **News Analyst**: Company news, macro events, Reuters feeds
  - **Fundamentals Analyst**: Financial statements, valuation, P/E ratios

- **Researcher Reports** (2): Generated via multi-round LLM debate:
  - **Bull Researcher**: Arguments FOR investing (growth, tailwinds, value)
  - **Bear Researcher**: Arguments AGAINST investing (risks, headwinds, concerns)

**Loading Mechanism** (from `rl_environment.py._load_llm_cache()`):
- During environment initialization, if cache file exists, all 17 reports are loaded into memory
- If cache doesn't exist, reports are generated on-demand and saved immediately
- Confirmation message: `✓ Loaded 17 cached LLM reports from ...`

## 1.5 Analyst Team (4 Specialized Agents)

The Analyst Team synthesizes data from multiple sources to provide holistic market analysis. Each agent focuses on a specific aspect of market analysis.

### 1.5.1 Market Analyst Agent

**Goal**: Analyze market trends using technical indicators

**File Location**: `tradingagents/agents/analysts/market_analyst.py`

**Role**: Technical analysis and price pattern recognition

**Agent Profile**:
- **Skills**: Code execution, technical indicator calculation, price pattern analysis
- **Tools**: 
  - `stockstats_utils.py`: Calculates 60+ technical indicators
  - Price data from CSV cache
  - Technical analysis libraries (TA-Lib, custom implementations)
- **Constraints**: Focused on price action and momentum, not fundamental valuations

**Input Data**:
- Historical price data (OHLCV from CSV cache)
- 60+ technical indicators (computed via `stockstats_utils.py`):
  - Moving averages (SMA, EMA, 20-day, 50-day, 200-day)
  - Momentum indicators (RSI, MACD, Stochastic)
  - Volatility (Bollinger Bands, ATR)
  - Trend (ADX, Support/Resistance zones)
  - Volume analysis
  - Price momentum

**Processing**:
```
1. Load 7-30 day price lookback window
2. Calculate 60 technical features
3. Identify trend regime (uptrend, downtrend, consolidation)
4. Detect overbought/oversold conditions (RSI > 70 or < 30)
5. Find key support/resistance levels
6. Analyze volume strength and breakout probability
7. Generate concise summary
```

**Output**: `market_report`
- **Structure**: Text summary containing:
  - Technical trend summary (bullish/bearish/neutral)
  - Momentum signals (strength, divergences, crossovers)
  - Key price levels (resistance, support, breakout targets)
  - Volatility assessment (ATR, Bollinger Bands state)
  - Entry/exit opportunity zones
- **Example**: 
  ```
  Technical Analysis Summary for HDFCBANK.NS
  ================================================
  RSI: 65 (approaching overbought), MACD positive crossover, 
  price above 50-day MA. Weekly consolidation with support at ₹1450.
  
  Bullish Signal: Price breakout above ₹1580 likely targets ₹1650.
  Bearish Signal: Failure to hold ₹1520 reverses bias below ₹1480.
  
  Volume: Above average on recent rallies, confirms buying interest.
  Verdict: Mild bullish bias, wait for breakout confirmation.
  ```

**Storage**: Saved in cache under key `market_report`

**File Path**: `tradingagents/dataflows/data_cache/llm_reports/TICKER_START_END.json["TICKER_YYYY-MM-DD"]["market_report"]`

### 1.5.2 Sentiment Analyst Agent

**Goal**: Analyze social media sentiment trends and retail investor behavior

**File Location**: `tradingagents/agents/analysts/social_media_analyst.py`

**Role**: Social media sentiment tracking and behavioral analysis specialist

**Agent Profile**:
- **Skills**: Web search, sentiment calculation, trend analysis, engagement metrics
- **Tools**:
  - Reddit search API (`reddit_utils.py`)
  - Twitter/X search (if configured)
  - Sentiment scoring (TextBlob, VADER, or FinBERT-based)
  - Trend detection algorithms
- **Constraints**: Focuses on retail/social sentiment, not institutional moves

**Input Data**:
- Reddit posts (via `reddit_utils.py`):
  - Subreddits: r/IndianStreetBets, r/wallstreetbets (if US stocks)
  - Search keywords: stock ticker, company name
  - Post metadata: upvotes, comments, timestamp
- Twitter/X sentiment (if configured)
- Sentiment scoring: -1 (bearish) to +1 (bullish) scale
- Engagement metrics: Upvotes, shares, comments, trending status
- Historical sentiment trends (7-day rolling average)

**Processing**:
```
1. Scrape recent posts/tweets mentioning the stock
2. Tokenize and score sentiment (-1 to +1 scale)
3. Aggregate into daily/weekly sentiment summary
4. Identify sentiment spikes and trend reversals
5. Calculate bullish vs. bearish comment ratios
6. Track social volume changes (3x more mentions = 3x social interest)
7. Assess retail conviction level (low/moderate/high)
```

**Output**: `sentiment_report`
- **Structure**: Sentiment time-series and engagement summary containing:
  - Sentiment peaks/trough dates and values
  - Daily/weekly sentiment averages
  - Bullish vs. bearish ratio
  - Social volume trends
  - Retail conviction level
  - Notable sentiment reversals
- **Example**:
  ```
  Social Sentiment Analysis for HDFCBANK.NS (Nov 4-19, 2024)
  ===================================================
  
  Sentiment Peak: Nov 15 (+0.65), "Dividend announcement incoming"
  Sentiment Trough: Nov 10 (-0.42), "Rate hike concerns"
  
  Weekly Average Sentiment: +0.42 (moderately bullish)
  Bullish Comments: 62%, Bearish Comments: 28%, Neutral: 10%
  
  Social Volume: 150 posts this week (up 3x from last week)
  Reddit Mentions: 89 (80% positive context)
  Twitter Engagement: 12,500 impressions, +300% from baseline
  
  Retail Conviction: Moderate Bullish (increasing discussion)
  Verdict: Positive retail sentiment, but monitor for exhaustion
  ```

**Storage**: Saved in cache under key `sentiment_report`

**File Path**: `tradingagents/dataflows/data_cache/llm_reports/TICKER_START_END.json["TICKER_YYYY-MM-DD"]["sentiment_report"]`

### 1.5.3 News Analyst Agent

**Goal**: Analyze global economic trends and events affecting markets

**File Location**: `tradingagents/agents/analysts/news_analyst.py`

**Role**: News aggregation and event impact assessment specialist

**Agent Profile**:
- **Skills**: News search, event classification, impact forecasting
- **Tools**:
  - Google News API (`googlenews_utils.py`)
  - Finnhub financial news
  - Reuters feeds (if available)
  - Event classification and impact scoring
- **Constraints**: Focuses on recent events, not historical analysis

**Input Data**:
- News articles from multiple sources (via `googlenews_utils.py`, `finnhub_utils.py`):
  - Company announcements, press releases
  - Macroeconomic news:
    - RBI policy changes, interest rate decisions
    - Inflation data, GDP growth
    - Government policy announcements
  - Sector-specific news (banking regulation, credit growth)
  - Earnings announcements, analyst upgrades/downgrades
  - Geopolitical events
- News sentiments and implications
- Catalyst calendars (scheduled events)

**Processing**:
```
1. Fetch recent news about stock and sector
2. Classify news by type (earnings, policy, competitive, macro)
3. Extract key events and numerical implications
4. Assess sentiment (bullish/bearish/neutral)
5. Prioritize high-impact events (earnings > policy > opinion)
6. Forecast short-term (1-2 weeks) vs. medium-term (1-3 months) impact
7. Calculate probability-weighted price targets
```

**Output**: `news_report`
- **Structure**: Key events with timeline and impact containing:
  - Recent news events (last 7-30 days)
  - Event type (earnings, policy, etc.)
  - Expected price impact (% range)
  - Catalyst dates and timelines
  - Uncertainty assessment
  - Macro context
- **Example**:
  ```
  News & Events Analysis for HDFCBANK.NS (Recent Developments)

  RISK: Deposit Competition Rising
  Details: Recent analyst reports highlight fintech pressure on deposits
  Impact: Negative for funding costs (-1% to -2% NIM pressure)
  Timeline: Ongoing, no specific catalyst
  Conviction: Medium-High (structural trend)
  
  NEUTRAL: Quarterly Earnings (Oct 26, reported)
  Results: Guidance maintained, no surprises
  Impact: Slight negative on growth concerns (-0.5% near-term)
  
  Macro Context: US inflation cooling, INR strengthening
  Positive for: Credit growth, fund inflows
  
  Net Assessment: Moderately bullish (rate cuts > deposit pressure)
  3-month target: ₹1600 (+5% upside), assuming rate cuts materialize
  ```

**Storage**: Saved in cache under key `news_report`

### 1.5.4 Fundamentals Analyst Agent

**Goal**: Analyze & evaluate company financials & stock performance

**File Location**: `tradingagents/agents/analysts/fundamentals_analyst.py`

**Role**: Financial statement analysis and valuation specialist

**Agent Profile**:
- **Skills**: Financial analysis, valuation modeling, ratio analysis
- **Tools**:
  - Financial statement data retrieval (`yfin_utils.py`)
  - Valuation models (DCF, relative valuation)
  - Ratio calculation engines
  - Peer benchmarking databases
- **Constraints**: Focuses on financial metrics, not macro-level policy

**Input Data**:
- Quarterly financial statements (via `yfin_utils.py`):
  - Income Statement: Revenue, Operating profit, Net income, EPS
  - Balance Sheet: Assets, Liabilities, Equity, Cash, Debt
  - Cash Flow Statement: Operating CF, Free CF, Capex
- Key financial ratios:
  - P/E ratio (Price-to-Earnings), P/B ratio
  - ROE (Return on Equity), ROA (Return on Assets)
  - Debt-to-Equity, Interest Coverage
  - Current Ratio, Quick Ratio, Operating margins
- Valuation metrics:
  - Dividend yield, payout ratio, PEG ratio
  - Enterprise Value, Free Cash Flow Yield
- Historical financial trends (3-5 year history)
- Industry benchmarks and peer comparisons

**Processing**:
```
1. Load quarterly/annual financial statements (3-5 years)
2. Calculate 20+ key financial ratios
3. Compare against industry peers and historical averages
4. Calculate intrinsic value (DCF, relative valuation methods)
5. Assess profitability quality and sustainability
6. Identify leverage/liquidity risks
7. Project medium-term earnings growth (1-3 years)
8. Flag red flags (deteriorating margins, rising leverage)
9. Assess dividend sustainability and payout ratios
```

**Output**: `fundamentals_report`
- **Structure**: Valuation and financial health summary containing:
  - Valuation assessment (cheap/fair/expensive vs. peers)
  - Profitability trends (margin expansion/compression)
  - Growth projection (earnings CAGR over 3 years)
  - Risk profile (leverage, liquidity, cyclicality)
  - Dividend sustainability
  - Intrinsic value estimate with range

  - Analyst report querying
  - Debate facilitator
  - Historical comparables database

- All 4 analyst reports (market, sentiment, news, fundamentals)
- Historical stock performance during similar periods
- Comparable company multiples and valuations
- Tailwind factors for the sector
- Previous bear researcher arguments (if multi-round debate)

```

├─ Identifies positive signals across all dimensions

### 1.6.2 Bear Researcher Agent

  - Analyst report querying
  - Historical crisis database
  - Downside scenario modeling
- **Constraints**: Must advocate for HOLD/REDUCE perspective and highlight risks

**Input Data**:
- All 4 analyst reports
- Historical bear markets and banking crises
- Competitive threats and market share data
- Macro headwinds and recession indicators
- Peer underperformance during downturns
- Previous bull researcher arguments (if multi-round debate)

**Processing** (Multi-Round Debate):
```
Round 1: Bear Researcher Analysis
├─ Reads all 4 analyst reports
├─ Identifies negative signals and risks
├─ Constructs bearish narrative
├─ Highlights margin compression, competition, valuation concerns
├─ Presents worst-case scenarios
└─ Publishes initial bear_report

Round 2+ (If configured):
├─ Reviews bull researcher counterarguments
├─ Questions growth assumptions with alternative scenarios
├─ Emphasizes execution risks and structural headwinds
├─ Refines downside targets
└─ Debate loop continues for N rounds
```

**Output**: `bear_report`
- **Structure**: Risk thesis summary containing:
  - Bearish overview (why to HOLD/REDUCE)
  - Key risks (3-5 downside drivers)
  - Downside price targets
  - Stop-loss levels and exit triggers
  - Conviction level (50-100%)
  - Scenarios for different macro outcomes
- **Example**:
  ```
  BEAR INVESTMENT THESIS: HDFCBANK.NS
  ===================================
  
  RECOMMENDATION: HOLD / REDUCE
  Fair Value: ₹1,400
  Current Price: ₹1,515 (overpaid by ~7%)
  Downside Risk: ₹1,300-1,350 (-13% in stressed scenario)
  Conviction: 65%
  
  THESIS SUMMARY:
  While HDFCBANK maintains quality franchise, risks outweigh returns at current
  levels. NIM recovery timeline highly uncertain, deposit competition structural
  and accelerating, and valuation offers no margin of safety. Better entry points
  likely as macro uncertainty persists.
  
  KEY RISKS & HEADWINDS:
  1. NIM Compression Risk: Deposit costs up +40 bps YoY, pricing power limited
     - Fintech pressure sustainable and growing (upi adoption >90% online transactions)
     - Corporate deposits migrating to money market funds and alternatives
     - RBI rate cuts may not offset structural deposit cost inflation
  
  2. Deposit Volatility: Liabilities side deteriorating
     - Retail deposits growth slowing (+2% YoY vs. historical 5-7%)
     - Granular deposit base eroding (HNI deposits down, mass affluent deposits sticky)

     - Vulnerability to rate spikes and fund outflows
  
  3. Valuation: No Margin of Safety
     - 18x P/E = 1.8x P/B (fair value, not cheap)

     - Limited upside to fair value, significant downside in recession
     - Dividend yield 2.8% = 0.28% real yield (negative in high inflation scenario)
  
  4. Credit Growth at Risk
     - Macro slowdown emerging (manufacturing PMI 54.5, declining trend)
     - Unemployment rising, consumer credit stress increasing
     - Corporate capex cycle weak (capex as % of GDP declining)
     - Asset quality could deteriorate faster than expected (NPA trend reversing)
  
  5. Structural Headwinds
     - Digital disruption accelerating fintech competition

```python
# Pseudo-code from RewardCalculator class
def calculate_reward(self, previous_portfolio_value, current_portfolio_value, action):
    """
    Calculate reward based on portfolio P&L
    
    Args:
        previous_portfolio_value: Portfolio value at start of week
        current_portfolio_value: Portfolio value at end of week
        action: Action taken (0: HOLD, 1: BUY, 2: SELL)
    
    Returns:
        reward: Scalar reward value (can be positive or negative)
    """
    
    # 1. Calculate P&L percentage
    pnl_pct = (current_portfolio_value - previous_portfolio_value) / previous_portfolio_value
    
    # 2. Base reward: percentage return
    base_reward = pnl_pct * 100  # Scale to reasonable range (e.g., -50 to +50)
    
    # 3. Transaction cost penalty (if action is BUY or SELL)
    transaction_cost = 0.001  # 0.1% per trade
    if action == 1:  # BUY
        transaction_cost_penalty = transaction_cost * 100
    elif action == 2:  # SELL
        transaction_cost_penalty = transaction_cost * 100
    else:  # HOLD
        transaction_cost_penalty = 0
    
    # 4. Final reward
    final_reward = base_reward - transaction_cost_penalty
    
    return final_reward
```

            # Compute Q-target
            with torch.no_grad():

            q_predictions = agent.network(states).gather(1, actions.unsqueeze(1))
            
            # MSE Loss with reward signal
            loss = F.mse_loss(q_predictions, q_targets.unsqueeze(1))

**Key Points about Reward Calculation**:

| Aspect | Details |
|--------|---------|
| **Timing** | After each trading week (every 5 trading days), triggered in `env.step()` |
| **Input** | Previous portfolio value, current portfolio value, action taken |
| **Formula** | `reward = (P&L % × 100) - (transaction_cost × 100 if action in [BUY, SELL])` |
| **Range** | Typically -10 to +10 (scaled percentage) |
| **Positive** | When portfolio gains value (exploited by agent during training) |
| **Negative** | When portfolio loses value OR excessive trading (penalizes poor decisions) |
| **Transaction Cost** | Applied immediately on BUY/SELL, creates friction for overtrading |
| **Encourages** | Long-term growth, profitable holds, strategic entries/exits |
| **Penalizes** | Losses, frequent trading, poor timing |
| **Learning** | Agent learns via Bellman equation: `Q(s,a) ← reward + γ × max(Q(s',a'))` |

## 3.3 Deep Q-Network (DQN) RL Algorithm with Reward Integration

The DQN agent learns an optimal trading policy through value-based reinforcement learning, integrating reward signals to maximize portfolio performance.

### How DQN Works in This Project

**1. Agent Observes State**
```
Current Week (e.g., Week 5 of 17):
  ├─ Price data: Close=₹1520, RSI=58, MACD=+0.15, ATR=25
  ├─ Market analyst report: "Technical uptrend, momentum positive"
  ├─ Sentiment report: "Retail bullish +0.62, Reddit mentions up"
  ├─ News report: "RBI rate cuts expected, sector bullish"
  ├─ Fundamentals report: "ROE 15%, P/E 18x, fair valuation"
  ├─ Bull report: "Growth drivers strong, NIM recovery expected"
  ├─ Bear report: "Deposit costs sticky, competition rising"
  │
  └─→ State Encoder converts to 9240-dim vector
       ├─ 6 report embeddings: 6144 dims
       ├─ 60 technical indicators (30-day): 1800 dims
       ├─ Portfolio state (cash, holdings, value, flag): 4 dims
       └─ Price features (OHLC window): 20 dims
```

**2. DQN Computes Q-Values**
```
DQN Network (PyTorch):
  Input: state_vector (9240 dims)
    ↓
  Hidden Layer 1: 512 neurons (ReLU activation)
    ↓
  Hidden Layer 2: 256 neurons (ReLU activation)
    ↓
  Hidden Layer 3: 128 neurons (ReLU activation)
    ↓
  Output Layer: 3 neurons (one per action)
    ↓
  Q-values = [Q(HOLD), Q(BUY), Q(SELL)]
  
  Q-value interpretation:
    Q(action) = Expected cumulative reward if taking action in current state
    
  Example output:
    Q(HOLD) = 0.32  (Expected future reward from holding)
    Q(BUY)  = 0.58  ← Highest (argmax) - Best expected return
    Q(SELL) = 0.05  (Lowest expected return)
```

**3. Agent Selects Action**
```
Action Selection Strategy (Greedy, during evaluation):
  
  best_action = argmax([Q(HOLD), Q(BUY), Q(SELL)])
  
  In example above:
    best_action = 1 (BUY)
    Confidence: Q(BUY) - Q(HOLD) = 0.58 - 0.32 = 0.26 (moderate)
    
  Execute: Buy int((cash × 0.2) / price) = 13 shares @ ₹1520
  
  Portfolio Update:
    Before: cash=₹10,000, holdings=0, total_value=₹10,000
    After:  cash=₹7,040, holdings=13, total_value=₹10,000 (unchanged at purchase)
```

**4. Environment Returns Reward & Next State**
```
Reward Calculation (Triggered in rl_environment.py.step()):
  
  After BUY action, at end of week (7 days), price moves to ₹1540:
  
  ├─ Portfolio value calculation:
  │  ├─ Holdings value: 13 × ₹1540 = ₹20,020
  │  ├─ Cash remaining: ₹7,040
  │  └─ Total portfolio: ₹20,020 + ₹7,040 = ₹27,060
  │
  ├─ UNREALIZED P&L (Before Reward):
  │  ├─ Entry value: ₹10,000 (initial capital)
  │  ├─ Current value: ₹27,060
  │  ├─ Absolute gain: ₹7,060
  │  └─ P&L %: (7,060 / 10,000) × 100 = 70.6%
  │
  ├─ WEEKLY PERIOD P&L (Used for Reward):
  │  ├─ Previous week-end value: ₹10,000
  │  ├─ Current week-end value: ₹27,060
  │  ├─ Weekly change: ₹7,060
  │  └─ Weekly P&L %: (7,060 / 10,000) × 100 = 70.6%
  │
  └─ REWARD CALCULATION:
     ├─ Base reward: 70.6% × 100 = 70.6 (very positive!)
     ├─ Transaction cost (BUY): -0.1%
     ├─ Final reward: 70.6 - 0.1 = 70.5
     │
     └─ Agent learns: "This state-action pair produced strong reward"
        Q(state, BUY) will be updated upward in next training iteration
```

**5. Transition Storage & Learning (Training Phase)**
```
During training, the agent stores all transitions:
  (state_t, action_t, reward_t, state_t+1, done) → Replay Buffer
  
  Example transition stored:
  {
    "state": [0.12, 0.45, ..., 9240 floats total],
    "action": 1 (BUY),
    "reward": 70.5,  ← Key: reward signal from portfolio P&L
    "next_state": [0.18, 0.51, ..., 9240 floats total],
    "done": False
  }
  
  The DQN periodically (every N steps):
  1. Samples minibatches from replay buffer (e.g., 64 samples)
  2. For each transition in batch:
     ├─ Compute target Q-value using Bellman equation:
     │  Q_target = reward_t + γ × max(Q(state_t+1, a))
     │            = 70.5 + 0.99 × max(Q([0.18, 0.51, ...], [0,1,2]))
     │
     ├─ Compute current Q-prediction:
     │  Q_pred = Network(state_t)[action_t]
     │
     └─ Compute loss:
        Loss = (Q_pred - Q_target)²  ← MSE between predicted and target
  
  3. Backpropagate loss: ∂Loss/∂Weights
  4. Update network weights: Weights ← Weights - LR × ∇Loss
  5. Update target network every N_target steps (target stabilization)
  
  Result: Q-network learns to predict better rewards for good state-action pairs
```

### Complete DQN Training Example

```python
# Pseudo-code showing reward integration during training
class DQNAgent:
    def train_step(self):
        # Sample batch from replay buffer
        states, actions, rewards, next_states, dones = self.replay_buffer.sample(64)
        
        # Compute Q-targets with reward signals
        with torch.no_grad():
            next_q_values = self.target_network(next_states)
            max_next_q = next_q_values.max(dim=1)[0]
            # Bellman backup: incorporate reward here
            q_targets = rewards + GAMMA * max_next_q * (1 - dones)
            #            ^^^^^^^ ← Reward signal drives learning!
        
        # Compute current Q-predictions
        q_predictions = self.network(states).gather(1, actions)
        
        # MSE loss: penalizes divergence from reward-based targets
        loss = F.mse_loss(q_predictions, q_targets)
        
        # Backpropagation: reward signal flows backward through network
        loss.backward()
        self.optimizer.step()
        
        return loss.item()
```
